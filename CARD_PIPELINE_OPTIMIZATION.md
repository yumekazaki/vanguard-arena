## Bottlenecks and measured work

1. **Repeated full-catalog parsing in catalog regressions.** The 95-test catalog file contained 84 parser call sites. One uncached pass through all 14,022 cards takes about 3.4 seconds. Returning a JSON clone from a parse cache was slower: three passes took about 12.1 seconds versus 9.5 seconds without caching, so that candidate was rejected.
2. **Long regression feedback.** The full suite took 245.62 seconds before safe immutable snapshots. The catalog regression file initially took 16.61 seconds after its calls were switched to snapshots.
3. **Manual interpretation of unsupported abilities.** 13,432 ability blocks remain unsupported or unreviewed. This is the largest completion backlog, but repository logs cannot substantiate the reported 22 or 32 hours. The optimization is to add reusable exact wording patterns and validate each matching card in batches; ambiguous wording remains unsupported until reviewed.

## Bounded parallel staging benchmark

`scripts/card-processing-pipeline.js` assigns deterministic catalog shards to a bounded `worker_threads` pool. Workers use the existing parser and reviewed definitions, write isolated shard files under ignored `.card-pipeline/staging/<run-id>/`, and never edit shared engine or card-definition files. The parent checks shard/card identities, ability counts, and output hashes, then atomically updates the run manifest. Resume is refused if the catalog, evidence manifest, engine/definitions, or batch size changed; a valid shard left by an interrupted run is recovered after identity and hash checks. Maximum workers are capped at eight and batch sizes at 2,000.

On this machine (8 logical CPUs, 15.9 GiB RAM, 2.9 GiB free when measured), an earlier fresh 14,022-card benchmark with batch size 1,000 took 5.11 s at one worker, 3.55 s at two, 2.80 s at four, and 2.63 s at eight. Eight workers processed about 319,600 parsed catalog records per minute; this measures parsing and audit only, **not** verified-card throughput. The pool stops at eight because that is the available logical CPU count; this short benchmark did not establish a better setting above eight. That earlier audit reported 1,517 cards with all abilities structurally implemented, 179 evidence-backed ability blocks, zero fully verified cards, zero invalid definitions, and 10,324 cards still awaiting review. The current full suite and evidence totals are recorded separately below.

The latest clean eight-worker run after adding 14 exact Legion-Vanguard boost abilities and canonical mate-ID validation completed in 2.36 s (about 356,630 parsed records per minute) with validation evidence fresh: 3,523 of 17,240 ability blocks compiled, 202 blocks with explicit passing regression evidence, zero invalid definitions, and zero fully verified cards. Unsupported and unreviewed cards remain at 10,310 because each of those has at least one unsupported ability. This is a parsing/audit throughput result, not verified-card throughput; the Legion activation that populates the mate link remains unsupported.
